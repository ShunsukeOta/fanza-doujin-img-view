# 作品共有・詳細検索・保存設計

## 前提

本サービスの実データ・API・DB・ReaderはFANZA同人コミックのみを対象とする。作品種別の切替UIや未公開機能の導線は持たず、`works`、CatalogService、SearchService、保存API、推薦、FANZA同期のすべてをコミック専用のDomainとして扱う。

## 作品共有

- canonical作品URLは `/work/{cid}`
- 旧 `/?cid={cid}` は301でcanonicalへ統一する
- `work.php` がDBから作品情報を取得し、React起動前にOGP / X Card / canonicalをHTMLへ埋め込む
- 共有URLは年齢確認後、対象作品Readerへ直接入る
- 作品URLのindex可否はSEO公開方針と分離して管理する

## 詳細検索

- `/search` をFeed内絞り込みSheetとは独立した検索画面として提供する
- `/api/search` → `SearchService` → MariaDB の責務分離とする
- 作品名・サークル・シリーズ・ジャンル・価格・最低評価・最低サンプル枚数・最低レビュー件数・並び順を検索可能とする
- 検索結果から `/work/{cid}` へ遷移してReaderを開始できる
- 購入意図が明確な利用者向けに、検索結果カードからFANZAへ直接移動できる導線を併設する

## 保存済み

- `/saved` は保存したコミックを一覧表示する
- 保存時価格と現在価格を比較し、値下げがある場合は差額を分かりやすく表示する
- 保存結果から `/work/{cid}` へ戻してReaderを開始できる
- 販売中の作品にはFANZAへの直接導線を表示する

## グローバルメニュー

下部メニューは「読む / 検索 / 保存 / マイページ」の4項目とする。

- 読む: メインReaderへ戻る
- 検索: 詳細検索へ移動する
- 保存: 保存済み作品へ移動する
- マイページ: 履歴・設定・利用データ管理へ移動する

メインReaderからサブページへ移動した場合は、作品CIDとページ位置を端末内に一時保存し、「読む」で元の閲覧位置へ復帰できるようにする。

## 不変条件

- `works` に存在する作品はFANZA同人コミックのみ
- 動画URLや作品種別を表すDB列を追加しない
- 検索・保存・履歴・推薦で別Domainの作品を混在させない
- ユーザー画面に将来予定や内部実装上の都合を表示しない
